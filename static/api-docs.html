공통 API에 수신함별 송신 키와 평문을 보내세요. Relay 대기열에 접수한 문장을 Muse의 클라우드 VM이 폴링해 VM 내부 localhost 수신기로 전달합니다.

시작하기평문 POST재시도와 중복 방지기기·수신기 연결수신 상태·보관관리·기기 인증기존 VM오류 응답

1. 수신함의 송신 API 키 발급

홈에서 계정과 수신함을 만들고 ‘송신 API 키 발급’을 누르세요. 발급 직후 ‘Codex·외부 프로그램용 사용법 복사 (키 포함)’로 한 번에 복사할 수 있습니다. 키 원문은 다시 조회할 수 없으므로 안전한 비밀 설정에 보관하세요.

POST /api/send
Authorization: Bearer 발급받은송신키
Content-Type: text/plain; charset=utf-8

작업 결과를 정리해서 알려줘.

서버가 송신 키로 수신함을 찾습니다. Muse ID·JSON·직접 정하는 메시지 ID는 필요 없습니다. 키가 없거나 잘못됐거나 교체·폐기됐다면 HTTP 401입니다. 계정마다 수신함을 따로 관리하고 각 수신함은 서로 다른 송신 키를 사용합니다. 공개 수신은 지원하지 않습니다.

2. JavaScript 서버에서 보내기

const endpoint = process.env.MUSE_API_URL; // 관리 화면의 공통 API 주소
const response = await fetch(endpoint, {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + process.env.MUSE_API_KEY,
    'Content-Type': 'text/plain; charset=utf-8'
  },
  body: '작업 결과를 정리해서 알려줘.'
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
console.log(await response.json());

처음 접수 시 HTTP 201과 아래 응답을 반환합니다.

{"id":"msg-자동생성값","created":true}
  • 송신 API는 Authorization 헤더를 포함한 CORS를 허용합니다. 쿠키는 보내지 마세요. 키를 공개 프런트엔드 코드·URL·로그에 넣지 말고 신뢰하는 실행 환경의 MUSE_API_KEY로 보관하세요. 관리 API와 기기 API의 인증은 별도입니다.
  • 문장은 UTF-8 기준 최대 16,384 bytes이며, 빈 문장은 거절합니다.
  • 수신함마다 분당 60건, 미전달 메시지 최대 1,000개입니다. 초과 시 HTTP 429가 반환됩니다.
  • 응답은 서버 접수 확인입니다. 기기 수신이나 Muse 작업 실행 완료를 뜻하지 않습니다.

3. 재시도와 중복 방지

같은 문장을 새 요청으로 보내면 별도 메시지입니다. 통신 실패 후 재시도할 때는 선택 사항인 Idempotency-Key에 고유값을 넣고 같은 요청에만 재사용하세요. ID를 사용자가 정할 필요는 없습니다.

Idempotency-Key: 클라이언트가자동생성한고유값

같은 키·본문이면 HTTP 200, created:false와 기존 ID를 반환합니다. 같은 키에 다른 본문이면 HTTP 409입니다. 네트워크 오류·5xx처럼 접수 여부가 불확실하거나 429인 경우 본문과 키를 유지해 재시도하세요. 확실한 입력 오류는 수정한 뒤 새 키로 요청하세요. 웹 전송 화면과 관리 화면의 테스트 버튼은 키를 자동 관리합니다. 완료 내역·키는 30일 보관 후 정리하므로, 오래된 요청을 다시 보내면 새 메시지가 될 수 있습니다.

4. 원하는 Muse 대화에 붙여넣어 연결하기

웹에서는 수신함을 만듭니다. 그 수신함의 연결 프롬프트를 붙여넣은 대화의 Muse가 자신의 VM을 연결합니다. API의 muse_id는 Relay 수신함 ID이며 Meta AI 계정 ID가 아닙니다.

Muse는 클라우드 작업 환경을 다루는 Meta AI 인터페이스입니다. 사용자는 터미널 설정 대신 관리 화면의 ‘연결 프롬프트 만들고 복사’를 눌러 Muse 대화에 붙여넣으세요. 선택한 수신함의 실제 서버 주소·다운로드 주소·10분 일회용 코드와 수행 순서가 자동으로 들어갑니다.

  1. 계정과 수신함을 만든 뒤 연결 프롬프트를 복사합니다.
  2. Muse에게 그대로 붙여넣습니다. Muse가 자신의 환경에서 수신함 준비·설치·연결과 부팅 시 자동 시작·메시지 처리 재개를 설정하도록 요청합니다.
  3. Muse가 준비됐다고 알려주면 웹의 테스트 버튼을 누르고 수신기 ACK를 확인합니다.

유효한 프롬프트는 같은 코드로 다시 복사합니다. 새 발급은 이전 미사용 코드를 무효화합니다. 만료·사용된 코드는 새 프롬프트로 교체하세요. 일회용 코드는 연결할 Muse 대화에만 전달하고 장기 기기키·계정 비밀번호는 공유하지 마세요. 자동 복사가 차단되면 프롬프트 미리보기에서 전체 선택해 복사할 수 있습니다.

Muse가 실제 터미널·Python 3.10 이상·네트워크·백그라운드 실행 도구를 사용할 수 있는지 확인하도록 안내합니다. 지원되지 않는 도구나 상시 실행을 보장하지 않습니다. 프롬프트는 영구 저장 경로에 설정과 메시지별 처리 기록을 보관하고, 재시작 후 수신기·중계기·Muse의 메시지 처리를 재개하도록 요청합니다. 정상 재시작·복구는 로그에만 남기고 사용자 조치가 필요한 지속 장애만 알리도록 안내합니다. Muse에게 실제 자동 시작 지원 여부와 복구 검증 결과를 확인하세요. 수신기 ACK는 Muse의 실제 읽기·작업 완료를 뜻하지 않습니다.

직접 설치하는 개발자를 위한 안내

관리 화면의 ‘직접 설정하기 · 고급 안내’를 펼쳐 ZIP 다운로드, 서버 주소가 포함된 connect 명령, 일회용 코드와 VM 내부 localhost URL을 사용하세요. python3 muse_agent.py run이 5초마다 조회합니다. HTTP 수신기는 JSON의 message를 영속 저장하고 중복 ID를 처리한 뒤 2xx를 반환해야 합니다. TCP는 받은 id와 ok:true를 JSON 한 줄로 반환합니다. 추가 Python 패키지는 필요 없습니다.

5. 전달 내역과 데이터 보관

로그인한 소유자만 해당 Muse의 내역을 볼 수 있습니다. pending은 기기 대기, leased는 가져간 상태, acked(수신기 ACK)는 localhost의 성공 응답을 확인한 상태입니다. 기기 온라인 표시만으로 수신기 ACK를 대신할 수 없습니다. 관리 화면에서 테스트 문장을 직접 전송하면 그 메시지 ID의 ACK를 확인합니다. Meta AI의 읽기·작업 실행 결과는 관측하지 않습니다.

HTTP 수신기는 payload.message로 문장을 받고, Idempotency-Key / X-Message-ID로 중복을 구분합니다. 성공 시 HTTP 2xx를 반환하세요. 응답 유실로 재전달될 수 있으므로 수신측에서도 중복을 방지해야 합니다.

완료 기록은 30일 후 큐 접근 시 정리하며, 사용하지 않는 Muse도 매시간 정리합니다. 대기 메시지는 보관합니다. 계정당 수신함은 3개까지 만들 수 있습니다. 초기 공개 버전에는 비밀번호 복구·결제·팀 기능이 없습니다.

관리·기기 API

관리 API는 HttpOnly muse_session 쿠키로 인증합니다. 쓰기 요청은 같은 Origin의 application/json이어야 합니다. 외부 송신자에게는 송신 키만 전달하세요. 관리 쿠키나 기기키를 배포하지 마세요. 송신 키는 전송만 허용하며 내역 조회·기기 claim/ack·키 관리는 허용하지 않습니다.

POST /api/auth/signup   {"username":"사용자명","password":"12자이상"}
POST /api/auth/login    {"username":"사용자명","password":"비밀번호"}
GET  /api/auth/me
POST /api/auth/logout  {}
GET  /api/muses
POST /api/muses        {"name":"내 수신함"}
GET  /api/muses/{muse_id}
POST /api/muses/{muse_id}/settings       {"name":"새 이름"}
POST /api/muses/{muse_id}/sender-key     {}  // 최초 발급·교체
POST /api/muses/{muse_id}/sender-key/revoke {}
POST /api/muses/{muse_id}/send           // 소유자 웹 전송: 같은 Origin의 text/plain
GET  /api/muses/{muse_id}/messages?limit=25&before=커서
GET  /api/muses/{muse_id}/messages/{id}
POST /api/muses/{muse_id}/pairing        {}
POST /api/muses/{muse_id}/device/revoke  {}

송신 키 원문은 발급 응답의 key에 한 번만 반환하며 서버에는 해시만 저장합니다. 수신함당 활성 키는 하나입니다. 교체 즉시 이전 키는 무효화되며 폐기하면 외부 전송이 중단됩니다. 기기 연결과 대기 메시지는 유지됩니다. 다른 수신함을 선택하거나 페이지를 새로고침하면 발급 원문은 지워집니다. 키를 잃어버렸다면 교체 후 모든 송신 프로그램의 설정을 갱신하세요.

다음은 연결 프로그램 전용입니다. 코드 교환 후 발급받은 Bearer 기기키는 해당 Muse의 claim·ack만 허용합니다.

POST /api/pair  {"code":"10분연결코드"}
POST /api/muses/{muse_id}/claim  {}
POST /api/muses/{muse_id}/messages/{id}/ack  {"lease_token":"점유토큰"}

기존 주소에서 전환하기

이 서비스의 기존 Muse별 공개 전송은 종료됐습니다. 기존 전용 주소를 호출하던 외부 프로그램은 공통 POST /api/send와 수신함별 송신 키로 변경하세요. Muse의 수신 연결과 대기 메시지는 유지됩니다. 기존 Muse별 send는 같은 Origin의 로그인한 소유자 웹 전송에만 사용합니다.

이 배포의 단일 VM /send도 기존 producer 인증이 필요합니다. 별도로 배포된 이전 VM 서비스는 이 배포의 대상이 아닙니다.

오류 응답

  • 400: 비어 있는 문장이나 잘못된 입력
  • 401: 송신 키 누락·오류·폐기, 로그인·기기 인증 필요 또는 만료된 연결 코드
  • 403: 관리 요청 Origin 확인
  • 404: 대상 없음 또는 소유자가 아닌 관리 요청
  • 409: 사용자 이름 중복·재시도키 본문 충돌·유효하지 않은 점유
  • 413: 본문 크기 초과
  • 415: Content-Type 확인
  • 429: 사용량 한도 초과, 잠시 후 재시도
  • 503: 저장소 일시 오류, 같은 요청키로 재시도

연결 확인은 인증 없는 GET /health를 사용하세요.
