# Muse Relay 사용 시작

[서비스 열기](https://muse-relay-production-b5b7.up.railway.app/) · [API 문서](https://muse-relay-production-b5b7.up.railway.app/api-docs)

Muse는 Meta AI를 뜻합니다. Muse Relay는 웹·Codex·API에서 받은 문장을 Muse의 클라우드 VM 내부 **localhost 수신기**로 전달합니다. 연결 프로그램은 Muse의 클라우드 VM 안에서 실행하고, VM 내부 수신기를 준비해야 합니다. Meta AI가 수신함을 읽고 처리하는 방법은 별도로 구성합니다.

## Muse에게 붙여넣어 연결하기

1. ‘시작하기’에서 계정을 만들고 Muse 이름과 공개 수신 여부를 정하세요.
2. 선택한 Muse의 **‘연결 프롬프트 만들고 복사’**를 누르세요. 서버 주소·연결 프로그램 ZIP·대상 Muse·10분 일회용 코드·설치와 검증 순서가 자동으로 들어갑니다.
3. **Muse 대화에 그대로 붙여넣으세요.** Muse가 자신의 클라우드 환경에서 실제로 가능한 도구를 확인하고 다운로드·수신기 준비·연결·폴링 시작을 수행하도록 요청합니다. 사용자가 터미널이나 JSON을 작성할 필요는 없습니다.
4. Muse가 준비됐다고 알려주면 웹의 **‘테스트 문장 보내기’**를 누르세요. 웹에서 해당 메시지의 수신기 ACK를 확인하고, Muse에게 수신함 도착과 실제 문장 읽기를 확인해달라고 요청하세요.
5. 전용 웹 전송 페이지나 API 주소를 사용하세요. 다른 Codex에는 ‘Codex·외부 프로그램용 사용법 복사’ 내용을 전달하면 됩니다.

## 프롬프트와 코드

유효한 프롬프트는 같은 일회용 코드로 다시 복사합니다. 새로 발급하면 이전 미사용 코드는 무효화됩니다. 10분이 지나거나 코드가 이미 사용됐다면 새 프롬프트를 만들어 Muse에게 전달하세요. 연결이 확인되면 코드와 프롬프트 표시는 지워집니다. 페이지를 새로 열면 다시 발급해야 합니다. 연결할 때 이전 기기 연결은 교체됩니다.

자동 복사가 막히면 **‘프롬프트 내용 보기 · 직접 복사’ → ‘전체 선택’**으로 복사하세요. 일회용 코드는 대상 Muse에게만 전달하고 공개 전송 페이지나 게시물에 올리지 마세요. 계정 비밀번호와 발급된 장기 기기키·로컬 인증값은 프롬프트에 포함되지 않습니다. `muse-connection.json`도 공개하지 마세요.

## Muse가 수행할 일과 확인 기준

프롬프트는 Muse에게 실제 VM 터미널/Python으로 서버 연결을 확인하고 프로그램 ZIP을 내려받도록 요청합니다. 기존 localhost 수신기가 있으면 재사용하고, 없으면 loopback 전용 수신함을 준비하도록 안내합니다. 실제 수신 URL을 확인한 뒤 Python의 `muse_agent.connect`로 코드를 교환하고 폴링 프로그램을 실행합니다. 기존 설정이나 프로세스는 덮어쓰지 않도록 요청합니다.

Muse가 필요한 도구·권한·네트워크·백그라운드 실행을 사용할 수 없는 환경이라면 제약과 실제 오류를 보고해야 합니다. 웹은 Meta AI 자체의 도구 사용이나 상시 확인 기능을 제공하지 않습니다. 지원되는 상시 확인·작업 재개 수단이 없다면 Muse가 제약과 필요한 조치를 알려야 하며, 처리 재개까지 설정됐다고 간주하지 마세요.

VM 온라인은 최근 폴링, 서버 접수는 대기열 저장, 수신기 ACK는 VM 내부 localhost 수신기의 성공 응답입니다. Muse가 문장을 읽고 작업을 끝냈는지는 Muse에게 별도로 확인하세요. 테스트 메시지는 사용자가 버튼을 눌렀을 때만 보내며, 정확한 메시지 ID의 ACK를 확인합니다. 테스트 기록은 탭의 sessionStorage에 Muse별로 보관됩니다.

## 직접 설정하는 경우

관리 화면의 **‘직접 설정하기 · 고급 안내’**를 펼치세요. Python 3.10 이상이며 추가 패키지는 필요 없습니다. 명령과 localhost 주소는 모두 Muse의 클라우드 VM 내부에서 사용합니다. HTTP 수신기는 JSON의 `message`를 영속 저장하고 `Idempotency-Key` / `X-Message-ID`로 중복을 방지한 뒤 HTTP 2xx를 반환합니다. TCP는 받은 ID와 `ok:true`를 JSON 한 줄로 응답합니다. localhost Bearer 인증이 필요하면 `connect --local-auth`를 사용하세요.

## 전송과 관리

공개 수신이면 송신자는 계정·키 없이 문장만 보냅니다. Muse별 주소에 대상이 고정되어 있습니다. 공개 수신을 끄면 로그인한 소유자의 웹 전송만 허용됩니다. 내역 조회·공개 수신 변경·기기 연결 해제는 소유자만 할 수 있습니다.

외부 API는 `POST /api/muses/{muse_id}/send` + `Content-Type: text/plain; charset=utf-8`, 본문은 문장 그대로입니다. 실제 주소는 관리 화면에서 복사하세요. ID와 JSON은 서버가 만듭니다. 통신 실패·5xx·429 후에는 같은 본문과 같은 `Idempotency-Key`로 재시도하세요. 새로운 문장에는 새 키를 사용하세요.

문장 최대 16KiB, Muse당 분당 60건, 대기 메시지 1,000개, 계정당 Muse 3개입니다. 기기가 꺼져 있으면 큐에서 기다립니다. 완료 기록과 재시도키는 30일 보관 후 정리됩니다.

[기존 VM 전송](https://vm-https-check-production.up.railway.app/legacy)은 계속 사용할 수 있습니다. 기존 `/send` 주소와 VM 설정은 그대로이며 새 Muse로 자동 이전하지 않습니다.

## VM 재시작 후 자동 복구와 알림

연결 프롬프트는 파일이 유지되는 VM에서 Muse가 다음을 직접 구성하고 검증하도록 요청합니다.

- 영구 저장 경로에 프로그램·비밀 설정·수신함·메시지 ID별 처리 기록과 재개 지침 보관
- 환경이 지원하는 부팅 시 자동 시작과 프로세스 감독으로 수신기·중계기·Muse의 수신함 확인 및 처리 재개, 중복 실행 방지
- 유효한 기기키 재사용, 일시 오류 재시도, 서버에 대기 중인 문장과 수신함의 미완료 작업 재개
- 완료된 작업 중복 처리 방지, 중단된 외부 작업의 성공 여부 확인 후 재개
- 정상 재시작·재연결·복구는 로그에만 기록. 최초 설정·테스트와 요청한 작업 결과는 보고하고, 복구 알림은 사용자 조치가 필요한 지속 장애·인증 실패·처리 정체만 중복 없이 보고

이는 Muse에게 전달하는 설정 요청입니다. 실제 자동 시작과 AI 처리 재개는 Muse 환경에서 검증해야 하며 웹의 수신기 ACK만으로 확인할 수 없습니다. 사용자 요청 없이 VM을 재부팅하지 않고, 실제 재부팅으로 검증하지 못한 부분은 구분하도록 요청합니다. 키가 폐기된 경우에는 새 연결이 필요합니다.
