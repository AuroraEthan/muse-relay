# Muse Relay 서비스 경험 개선안

## 목적
처음 방문한 사람이 무엇을 하는 서비스인지 이해하고, 자신의 Muse를 연결한 뒤 전용 전송 주소를 공유할 수 있게 한다. 기존 계정·메시지·API 계약과 VM 연결은 유지한다.

## 방향 비교
1. 추천: 서비스 소개와 실제 사용 공간을 분리하고 단계별 연결 안내를 제공한다. 가입부터 첫 전달까지 명확해지며 기존 백엔드를 활용할 수 있다.
2. 개발자 콘솔 중심: API·로그를 전면에 배치한다. 개발자에게 빠르지만 일반 사용자가 이해하기 어렵다.
3. 소개 화면만 변경: 작업 범위는 작지만 가입 이후의 혼잡함이 남는다.

## 제안하는 화면
- 방문자 홈: ‘내 컴퓨터의 Muse에게, 어디서든 메시지를.’이라는 설명, 시작하기·사용 방법 버튼, 실제 전달 흐름을 명시한 예시, 웹/Codex/API 사용 사례, 세 단계 사용법, FAQ. 가입 폼은 시작하기를 누른 뒤 명확한 가입/로그인 영역에서 보여준다.
- 내 Muse: Muse 목록, 기기 연결 상태, 최근 전달 시각과 메시지 상태를 구분해 보여준다. Muse가 없으면 첫 등록 작업 하나에 집중한다.
- 연결 안내: 등록 → 연결 프로그램 다운로드 → 연결 코드/현재 서버용 명령 복사 → 실행 → 테스트 메시지 전달 확인의 진행 상태를 보여준다. 기존 HTTP/TCP 수신 프로그램 필요 조건은 설정 단계에서 설명한다. 기기 온라인과 localhost 전달 성공을 혼동하지 않는다.
- 메시지 보내기: 대상 Muse 이름과 입력창, 보내기, 접수 결과를 중심에 둔다. 전송 중·실패·재시도와 비공개 수신 상태를 명확히 표시한다. 서버 접수와 전달 완료를 구분한다.
- API 문서: 시작하기, 내 전용 주소 찾기, text/plain POST 예제, 응답·오류·재시도 안내. 관리 화면에서 내 주소를 포함한 Codex용 안내를 복사한다.

## 시각 원칙
짙은 잉크색 본문과 밝은 바탕에 청록색 강조를 사용한다. 본문은 15~16px, 주요 제목은 크게, 보조 정보도 읽을 수 있는 크기로 정리한다. 동일한 버튼·입력·상태 배지·여백 규칙을 모든 화면에 적용한다. 모바일에서는 한 열로 진행한다. 실제로 확인하지 않은 이용자 수·가동률·보안 인증·후기를 표시하지 않는다.

## 구현 범위와 검증
Python 표준 라이브러리 서버와 현재 계정·Muse·폴링 API를 활용한다. 연결 상태는 기존 조회 API로 확인하고 테스트 전송은 소유자가 버튼을 눌렀을 때 선택한 Muse에만 보낸다. 기존 VM으로 자동 테스트를 보내지 않는다. 새 영속 데이터 구조·결제·비밀번호 재설정·소셜 로그인을 추가하지 않는다.

상태 표시와 연결 흐름 변경에 필요한 회귀 검증, 기존 API 테스트, 데스크톱/모바일 브라우저 검증을 수행한다. 별도 테스트 Muse에서 등록·연결·문장 전송·localhost 수신·ACK를 확인한다. 비공개 GitHub 저장소에 PR로 반영하고 CI 성공 후 Universe Railway 자동 배포와 데이터 보존을 확인한다.

## 승인 및 추가 요구사항
2026-10-20 사용자가 전체 흐름 개선과 구현·배포를 승인했다. Muse는 사용자가 말하는 Meta AI다. 소개·연결 안내·API 문서에 이를 반영하되, Relay는 Meta AI 자체를 제공하거나 실행하지 않으며 VM의 localhost 수신함까지만 전달을 확인한다. Meta AI가 해당 수신함을 읽고 처리하는 연결은 사용자의 실행 환경에서 별도로 구성해야 한다. 화면에서 작업 완료나 공식 연동을 암시하지 않는다.

## 사용자 목적 재확인
사용자는 서비스의 핵심이 ‘Muse의 클라우드 환경 VM과 외부의 연동’이라고 명확히 했다. 주 사용 대상은 일반 데스크톱·자체 호스팅 AI가 아니라 Muse(Meta AI)가 사용하는 클라우드 VM이다. 소개의 핵심 문구와 연결 명령 실행 장소를 이 대상으로 좁힌다. 외부 웹/Codex/프로그램 → Relay 보관 → Muse 클라우드 VM의 폴링 → VM 내부 localhost 수신함이 실제 데이터 경로다. localhost는 사용자의 브라우저가 있는 컴퓨터가 아니라 Muse 클라우드 VM 내부 주소다. Meta AI 환경을 직접 설치하거나 계정 인증을 Relay에 맡긴다는 오해를 만들지 않는다. 기존 전달·실행 상태 구분과 범용 설정/API는 유지한다.
